边缘分流源：ms-edge

续《第一镜像 / 第二镜像 OpenI》之后，这篇记一个不同的东西： 不是另一份素材树的「存放地」，而是一个站在字节源前面的分流边缘层。它跑在 ModelScope 创空间的容器里（:7860），把 /assets/** 与 /fonts/** 302 重定向到真实字节源 （当前指向自建 ModelScope 数据集镜像），字节不经容器；其余路径（页面 / data / js / ws / healthz）由容器里的游戏服务器回答。 事实来自 feat/ms-edge-origin 分支的 origins.json 与 src/origins.mjs（2026-10-11）。

1 结论先行 分流边缘层，不是镜像；已上线（2026-10-11 晚验收）

容器地址 https://jingjiangze-stronghold-protocol.ms.show：/assets/**、/fonts/** 302 跳到真实字节源；其余路径（页面 / data / js / ws / healthz）→ 游戏本体。本站不持有任何美术字节， 只做「把请求指到正确的源」这一件事——线上素材全走 CDN，字节不经服务器。
实现形态（2026-10-11 晚，已上线）：分流判定跑在游戏进程内（server/http/asset-jump.js）， 与容器侧 sidecar 共用同一份 sources.json 与同一组纯函数——nginx 形态在创空间用不上 （平台不执行我们的 CMD），进程内 302 覆盖同一职责。

为什么是 302 而不是反代：字节直接 302 出网，容器只承担一次重定向的极轻开销，不被几百 MB 素材流量拖垮； 且平台对容器有单实例端口与流量约束，让字节绕开容器最稳。
已上线（2026-10-11 晚）：/assets/** 302 实测通过（默认 → 数据集镜像、 ?sp_source=r2 → speedcdn、?sp_source=openi → OpenI），游戏页面仍由容器回答。 CDN 仓的 origins.json 已把 ms-edge 从 enabled:false 与 disabled 两处移除（同批接口重发）。
ARCHITECTURE

容器内分流架构

游戏进程内 302 + 同一份 sources.json（nginx 形态保留在仓库）

请求怎么走

  • /assets/**、/fonts/** → 游戏进程内的分流判定回 302 到真实字节源（与 sidecar 同一份规则与源表）。
  • 其余（/、/data/、/js/、/ws/、/healthz）→ 游戏本体回答，与素材无关。
  • 源表读不到时分流自动关闭（只记日志）——素材层故障不会把游戏拖下水。

实现取舍

  • 弃用 Lua、也不靠 nginx：先由 nginx+lua 改为普通 nginx + Node sidecar（lua 装配成本高、调试难），上线时又确认平台不执行我们的 CMD → 判定搬进游戏进程（asset-jump.js），与 sidecar 共用纯函数；两条路都能用，规则只有一处。
  • 真实字节源当前指向自建 ModelScope 数据集镜像（本仓 assets-raw 树的同源存放，非创空间页面本身）。
  • 容器地址由创空间强制端口 :7860，外部只能访问这个端口。
与三篇「镜像」的区别：OpenI / ModelScope 是「素材树的一份拷贝」（git 镜像）；ms-edge 是「在字节源前面的一层分流」， 自己不存字节。probe 必须点名真实素材路径（/assets/char/avatar/char_003_kalts.png）， 不能用默认 /robots.txt——否则会量到游戏服务器、把游戏页当镜像。
CONFIG

接入配置（origins.json）

extraOrigins 条目 + disabled 双写

它作为一条 extraOrigin 进入 art.json / mirrors.json， 由 src/origins.mjs 透传 probe 与 coverage。 仓库约定：parking 需条目级 enabled:false 与 disabled 列表双写。 

// origins.json —— extraOrigins（2026-10-11 晚起：不再停靠）
{
  "id": "ms-edge",
  "kind": "cdn",
  "root": "https://jingjiangze-stronghold-protocol.ms.show",
  "probe": "/assets/char/avatar/char_003_kalts.png",
  "coverage": "full"
}

// origins.json —— disabled（ms-edge 已移出；openi 保留：浏览器 CORS 不可用，只作边缘点名通道）
"disabled": [ "jsdelivr", "jsdelivr-assets", "openi" ]
启用已完成：条目里的 enabled:false 与 disabled 列表里的 "ms-edge" 两处已同步移除；客户端源表随 sync --interface-only 重发。 以后新增停靠（parking）仍须两处双写。

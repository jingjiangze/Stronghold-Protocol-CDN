边缘分流源：ms-edge

续《第一镜像 / 第二镜像 OpenI / 第三镜像 ModelScope》之后，这篇记一个不同的东西： 不是另一份素材树的「存放地」，而是一个站在字节源前面的分流边缘层。它跑在 ModelScope 创空间的容器里（:7860），把 /assets/** 与 /fonts/** 302 重定向到真实字节源 （当前指向自建 ModelScope 数据集镜像），字节不经容器；其余路径（页面 / data / js / ws / healthz）由容器里的游戏服务器回答。 事实来自 feat/ms-edge-origin 分支的 origins.json 与 src/origins.mjs（2026-10-11）。

形态 302 边缘 字节 不经容器 现状 停用待上线
1 结论先行 分流边缘层，不是镜像；当前默认停用（2026-10-11）

容器地址 https://jingjiangze-stronghold-protocol.ms.show，nginx 占 :7860 做分流：/assets/**、/fonts/** → Node sidecar（内部 :3130）返回 302 跳到真实字节源；其余 → 游戏服务器（内部 :3120）。本站不持有任何美术字节，只做「把请求指到正确的源」这一件事。

为什么是 302 而不是反代：字节直接 302 出网，容器只承担一次重定向的极轻开销，不被几百 MB 素材流量拖垮； 且平台对容器有单实例端口与流量约束，让字节绕开容器最稳。
当前默认 enabled:false：创空间容器需要人工在设置页「重新部署」才会重建镜像， 平台对 Running 态的容器拒绝重建。在那之前这个源的 /assets/** 是 404，所以先停着——验收通过后再去掉 enabled:false 与 disabled 列表里的条目。
ARCHITECTURE

容器内分流架构

nginx :7860 + Node sidecar :3130 + 游戏 :3120

请求怎么走

  • /assets/**、/fonts/** → nginx 转给 Node sidecar（:3130），sidecar 回 302 到真实字节源。
  • 其余（/、/data/、/js/、/ws/、/healthz）→ 游戏服务器（:3120）。
  • sidecar 挂掉时，nginx 兜底 return 302 主源，不把玩家卡在 502。

实现取舍

  • 弃用 Lua：原 nginx+lua 方案改为普通 nginx + Node sidecar——lua 在容器镜像里装配成本高、调试难，sidecar 用 JS 写更直观。
  • 真实字节源当前指向自建 ModelScope 数据集镜像（本仓 assets-raw 树的同源存放，非创空间页面本身）。
  • 容器地址由创空间强制端口 :7860，外部只能访问这个端口。
与三篇「镜像」的区别：OpenI / ModelScope 是「素材树的一份拷贝」（git 镜像）；ms-edge 是「在字节源前面的一层分流」， 自己不存字节。probe 必须点名真实素材路径（/assets/char/avatar/char_003_kalts.png）， 不能用默认 /robots.txt——否则会量到游戏服务器、把游戏页当镜像。
CONFIG

接入配置（origins.json）

extraOrigins 条目 + disabled 双写

它作为一条 extraOrigin 进入 art.json / mirrors.json， 由 src/origins.mjs 透传 probe 与 coverage。 仓库约定：parking 需条目级 enabled:false 与 disabled 列表双写。 

// origins.json —— extraOrigins
{
  "id": "ms-edge",
  "kind": "cdn",
  "root": "https://jingjiangze-stronghold-protocol.ms.show",
  "probe": "/assets/char/avatar/char_003_kalts.png",
  "coverage": "full",
  "enabled": false
}

// origins.json —— disabled 列表（与条目级 enabled:false 双写）
"disabled": [ "jsdelivr", "jsdelivr-assets", "openi", "ms-edge" ]
启用待办（验收通过后）：去掉条目里的 enabled:false 且从 disabled 列表移除 "ms-edge"——两处必须同步改，否则会被另一条发布分支悄悄复活 / 悄悄忽略。

## 一、真瓶颈：冷启动 5.4 MB 走盒子上行

| 口径 | 每人 | 10 Mbps 容纳 |
|---|---|---|
| **稳态**（客户端已缓存，纯 WS） | **57.5 B/s** | **≈21,000**（留 20% ≈17,000） |
| 60 分钟会话 + 冷启动（5.4 MB / 新玩家摊薄 1,573 B/s） | 1,630 B/s | **≈766** |
| 60 分钟会话，仅 1% 是新玩家 | 121 B/s | ≈10,300 |

**冷启动比对局流量贵 27 倍。** 而这 5.4 MB（`js` 2.5 MB + `vendor` 2.9 MB）**是盒子自己发的** ——
Cloudflare 实测 `cf-cache-status: MISS`，不吃 CF 缓存。`immutable` 只让**浏览器**缓存一年，
帮不到第一次进场的玩家。

⇒ **省带宽的优先级（按性价比排）**：

| 序 | 事项 | 量级 | 难度 |
|---|---|---|---|
| ① | **把客户端静态交给 CDN** | 每人次 5.4 MB → 0 | 中（要改发布链） |
| ② | `b.start` 进白名单 | −54.1% | **已做** |
| ③ | 隐藏标签页停推 | 省「人不在」的时段 | 低 |
| ④ | 把流改成拉 | 见 §四 —— **通常不省** | 高 |

## 二、还能做的三件（按性价比）

### ① 隐藏标签页停推（低风险、零可见影响）

客户端**已有** `visibilitychange` 钩子（`public/js/net.js`，现在只用来抑制链路探测）。
加一个轻量 intent 让服务端对**隐藏标签页**停推 / 降频，回前台走**已有的 resync** 拿全量。

- **影响面**：省的是「人不在」的时段；回前台有 resync 兜底。
- **验收**：切走 60 s 再切回，画面在 1 s 内恢复完整；切走期间该连接出站 ≈0。
- **退路**：intent 未声明 → 照常推（今天行为）。

### ② `PUBLIC_THROTTLE` 100 → 200 ms（需拍板）

`m.public` 实测 ~0.76–4 帧/s，**远未到** 100 ms 那个 10/s 上限 ⇒ 把上限放宽到 200 ms 能砍一部分字节，
代价是 **HUD（LP / 准备状态 / 倒计时 / boss 血条）最多晚 500 ms**。

- **未做**：这是可见的体验取舍，需要拍板，不是纯技术决定。

### ③ 把 ③④ 真正推上线（把 delta 默认打开 + 落进 master-play）

收益已实测（2.98× on `m.public`），但对人均的影响只有几个百分点 —— **排在上述两项之后**。

## 三、不要做（会砍可见内容）

**「客户端本地推演 + 服务端只发事件」**（把 `m.public` 全量也去掉）会**看得见地**砍掉：

1. **队友实时棋盘与羁绊** —— 事件化后靠本地回放，任何 RNG / 时序分叉就显示成错的。
2. **敌人预览与波次** —— 来自服务端 RNG，客户端复现不出。
3. **Boss 血池 / 团队 LP / 联防计数** —— 共享权威值，本地累加分叉即错。
4. **隐藏信息** —— 别人的商店 / 手牌服务端**故意不发**；要推演就得发 → 要么泄露（外挂面），要么推不出来。
5. **结算结果 `m.result`** —— **砍不掉**：客户端自算 = 可伪造胜负。
6. **倒计时 / 重连** —— 事件化后重连要重放整条事件日志，重连成本回来了。

**服务端不能放弃对结果 / 伤害的权威（否则就是外挂）。砍得掉的是保真度与预览，砍不掉权威层。**

## 四、附：「改成拉模式（pull）」的审计结论（只审计，未实施）

用户问过「能不能改成用户读服务器、服务器不主动发」。结论：**对玩家侧不省**。

- push 成本 = N × **变化率**；pull 成本 = N × **轮询率**。
- 要同等新鲜度，轮询率就得 ≥ 变化率 ⇒ **相同或更贵**。
- **pull 只在接收方不需要新鲜度时才省**：后台标签页、外部展示工具、排行榜。

⇒ 对局内广播**不要**改拉模式。真正该用 pull 的只有**观察者**那一类
（参考上游 PR #91 的 `GET /api/rooms/{code}/status`：不登录、不占席位、字段白名单）。
我们这套部署里大厅本来就走 HTTP 板 API，**观察者从不持会话** ⇒ 那条的实际收益主要来自
「第三方工具不再需要挂会话」，属**功能**而非节流。

详见独立库的 `docs/PULL-VS-PUSH.md`。

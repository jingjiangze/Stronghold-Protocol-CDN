素材 CDN

把上游（sganggs/Stronghold-Protocol） 的静态素材镜像到边缘，让部署机不再承担几百 MB 的重复流量。内容就是上游 Release 完整包里的同一批文件， 逐文件校验过，不做任何转码。

上游 … 文件 … 体积 … 校验 …

1 Agent：对所有服务器通用 读契约 · 按拓扑套做法 · 跑验收

不管目标是一份未修改的上游包、本项目的 fork、静态托管、nginx 反代还是 Docker，只有一条规则要遵守： 客户端取素材的唯一来源是清单（data/assets.json、local-assets.json、emotes.json）， 所以把这三张清单里 /assets/… 与 /fonts/… 的 URL 改写成 CDN 绝对地址即可， 不需要改客户端，也不需要改服务器代码。

四条硬约束

  • 只在响应层改写：服务器自己也要读这些清单做完整性校验，改磁盘文件会破坏更新与自检
  • 素材必须带 CORS：客户端用 img.crossOrigin='anonymous'，否则 WebGL 贴图被污染
  • URL 要带版本令牌：?v=<令牌>，否则改版后边缘缓存会继续发旧字节
  • 路径不要自己拼：清单里的地址已经是绝对 URL，照用

先确认目标长什么样

  • 找到部署目录：含 package.json 与 server/（或等价的服务入口）
  • 确认服务端口：GET /data/assets.json 能返回 JSON
  • 记下改写前的一个样本 URL，验收时对照
目标拓扑做法
任何 HTTP 服务（通用） 侧车代理：把服务起在内部端口，在外层代理，只改写三张清单的响应。下载 A（侧车包）用的就是这个，stronghold-cdn/cdn-serve.mjs 可直接抄（含 WebSocket 透传与 accept-encoding 处理）。下载 B（整合包）不用它：清单已经在包里被改成绝对 CDN 地址，服务端不需要任何改动。
本项目 fork 不需要代理，设环境变量即可：SP_ASSET_CDN=https://modelscope.cn/datasets/jingjiangze/Stronghold-Protocol-Assets/resolve/master/releases/v1-trial/（服务端 server/http/static.js 会改写三张清单；该值启动时读一次，改完要重启）。注意：这个开关是本项目 fork 加的，上游官方包没有——上游的 -lite.zip 里 grep 不到它，所以下载 B 走的是改清单而不是设变量。
nginx 反代 
location = /data/assets.json {
  proxy_pass http://127.0.0.1:3001;
  proxy_set_header Accept-Encoding "";   # 必须：否则拿到的是 gzip，替换不生效
  sub_filter '"/assets/'  '"https://modelscope.cn/datasets/jingjiangze/Stronghold-Protocol-Assets/resolve/master/releases/v1-trial/assets/';
  sub_filter '"/fonts/'   '"https://modelscope.cn/datasets/jingjiangze/Stronghold-Protocol-Assets/resolve/master/releases/v1-trial/fonts/';
  sub_filter_once off;
}
三张清单各写一条 location（assets / local-assets / emotes）。
静态托管（无服务端逻辑） 直接取 CDN 上的 /data/assets.json 覆盖本地的同名文件（它已经是绝对地址）。仅当没有服务端会读该文件做校验时才可这么做。
Docker 在容器里跑侧车（把服务入口改成 node cdn-serve.mjs），或按 fork 那条设 -e SP_ASSET_CDN=…。

验收（任何拓扑都跑同一套）

  1. 清单里 0 条素材仍指向本机：node verify-cdn.mjs http://127.0.0.1:<端口> 应输出 OK
  2. 抽样 20 条 CDN URL 全部 200（同一脚本会做）
  3. 浏览器冷启动：控制台 0 报错、棋盘贴图与干员立绘正常、房间能进能打
  4. 回退演练一次：停掉侧车（或去掉环境变量）后按原方式启动，页面仍正常

关于「部分覆盖」这个标记（2026-10-12 更新）：它曾经是对的 —— 素材树从上游发布包解出来后一直不进 git， 所以 git 挂载源只能给出本仓几十 KB 的工具文件，请求素材只会得到 404。这不是不稳定，是源里当时就没有。 现在已解决：素材树已于 2026-10-09 提交到本仓的 assets-raw 孤儿分支，2026-10-11 又补入 2,476 个皮肤文件，各源现在都能给出全部素材； 抽样 40 条路径 × 3 个源（jsDelivr / ghfast / gh-proxy）逐字节 sha256 校验一致，MIME、CORS 与 Range 206 均已实测。 注意：皮肤已随上游发布包一并进入 R2 / Pages（实测与 assets-raw 字节一致），同时 git 挂载层也以 coverage:full 提供。 唯一例外是 docs/（官方文档）：它只发布到 R2 / Pages，不在本仓里，所以 git 挂载源对它 404 —— 表格最后一列按实际标注。
2026-10-12 逐源复核口径已修正，这里同步更正：本页面的逐源覆盖率实测（30 个探针，只从上游集合 index.json 取样）结论是 —— openi / ghfast / jsDelivr 三个 git 挂载源均 28/30， 缺的只有 docs/；r2 / r2-alt / pages 30/30。 pages 是「慢」而不是「缺」：重试 + HEAD + Range 交叉验证后， 那几个看似超时的路径全部 200 且字节相符（中位 7 s、p90 93 s，854 KB 的音频取到过 612 s）。 另：fonts/ 在 git 挂载源里（早期「docs / fonts 只在 R2 / Pages」的说法， fonts 那半句已被实测推翻）。详见 逐源素材清单。

REFERENCE · PRELOAD

预载通道

一次拉完整棵树，之后都由本地发

整棵素材树按分组打成少数几个压缩包（每包约 96 MB）。逐文件取是延迟受限的；预载通道让部署机 在首次启动前把整批字节一次拉到本机，之后由本地直接发 —— dropin 的 SP_LOCALIZE=1 就是按这份清单拉包（SP_LOCALIZE_PACKS 可选子集，见 dropin/README.md）。 包只发布在 GitHub Release（assets-<tag>），对象存储不存包 —— 同一批字节只保留一份权威副本，避免两处各自漂移。

滚动更新（GitHub）：包名与链接都跟上游 tag 走。上游每次发新版， sync.yml（每天 4 轮、每 6 小时一次）重新打包并发布 assets-<新 tag> 下的一整套包；本表读的是发布接口里的 packs 字段，所以它跟着上游一起滚动，永远指向当前版本，不用记版本号。 每行右侧是同一个包的几条下载门牌：第一条是 GitHub 上的权威副本，后面是套了镜像前缀的加速入口。

GUIDE · BANDWIDTH

上行带宽最大化压缩

小上行带宽盒子的实测优化与容量表

如果你的部署机上行很小（家用宽带、4G 路由、小水管 VPS），这一份是为你写的。两件事要分开看： 首载是「新玩家第一次进场吃掉几百 MiB」（优化前 467.9 MiB，10 Mbps 上占死 6.5 分钟）， 靠把素材挪到 CDN 解决，优化后 1.48 MiB（316×）； 稳态整局实测人均 57.5 B/s，10 Mbps 约 21,000 人—— 2000 人不再是「刚好够」，而是有约 10 倍余量。 真正的瓶颈已经换了：不是 WS 帧，是新玩家冷启动那 5.4 MB 客户端代码 （1,573 B/s，比稳态贵 27×）。

GUIDE · P2P PLAY

openp2p 异地联机

阿里云 ECS · 经 Cloudflare 隧道 · 玩家无需公网 IP

玩家分散在各自家里、没有公网 IP 时怎么联机：房主把本地 3000 端口映射出去， 每个玩家在本地访问 127.0.0.1:3000 即等同于访问房主机房里的同一端口。 平台跑在阿里云 ECS 上，对外经 Cloudflare 隧道暴露；客户端只要能出站 UDP 即可。 有 p2p 直连能力时数据不经过服务器（ECS 默认 ShareBandwidth=0，只走信令）。

接口域名（2026-10-19 口径：本桶的规范门牌、order 第一位是 ms-dataset）：https://downcdn.jiangjiangze.icu —— 接口由站点自身提供（同源副本）；R2 域已退役，桶里只剩上传暂存，不再是对外入口。 weishucdn2（r2-alt）已于 2026-10-20 删域，仅返 Cloudflare 的 639 B 占位外壳，已登记 retired，不再作为接口门牌。实测 /cdn/v1/api.json sha256 完全相同；mirrors.json / index.json / tree.json / data/assets.json 均 200。 上面「来源」表里的其它主机名是素材镜像，不是第二个接口——它们只镜像素材树， 没有 /cdn/v1/ 这套接口文件（实测：Pages 源对该路径 404、git 源 502）。 所以：接口从站点自身（downcdn）取：它自带 cdn/v1 与 data/ 的同源副本，素材再从各镜像里挑最快的那个（下载页已按实测自动选）。

给 agent 的查询接口

没有服务端查询，所以"接口"就是三个静态文件加一个 HEAD 请求。按你要问的问题选：

要问什么怎么问代价
这个文件在不在、多大HEAD <基址>/assets/…1 个请求
这个文件有没有被改过GET /cdn/v1/index.json → 比 sha2561.6 MiB
某个目录里有什么GET /cdn/v1/tree.json → dirs["assets/spine/op/…"].files85 KiB gzip
整棵树 / 按名字搜同上，遍历 dirs85 KiB gzip

tree.json 的形状：dirs["<目录>"].files 是 [[文件名, 体积, 是否托管?], …]；mod=1 表示该文件是本仓刻意托管的第三方 mod 素材，不是上游内容。所有源都带 Access-Control-Allow-Origin: *，可以直接在浏览器或 Node 里取。

完整镜像链路同步方法

这篇把整条镜像同步链路一次讲清：从「上游发布 / 后台上传」进 R2 桶，到「发布轮 → git 链 → 各 git 镜像」的 字节级搬运，再到「排名测速」独立收尾。事实来自 main 分支的 Workflow 与实测 （2026-10-15），不估算。主门牌 https://speedcdn.jiangjiangze.icu； weishucdn / weishucdn2 / speedcdn 是同一个 R2 私有桶（stronghold-assets）的三个域名，字节完全相同，接口文件 （/cdn/v1/*.json）只挂在 R2 桶域名上。

真源 R2 三域名 中枢 assets-raw rank 独立收尾
1 结论先行 A→B→C 是字节流，D 是排名支线；git 链是中枢

字节只有一条主干：上游发布 / 后台上传 → 发布轮 → R2 桶（三域名）→ git-art → 孤儿分支 assets-raw → OpenI + 魔搭数据集 + ghfast/jsDelivr/gitcdn-own。 rank 链（D）是独立的排名 / 测速支线，只把「合格的实测源」排序信息喂给容器边缘，不改字节树本身。
硬依赖顺序：promote → git-art → openi/dataset-tree。git 链是中枢——OpenI 与魔搭数据集链都读 assets-raw；rank 独立，收尾重测。乱序会丢字节或让镜像落后。

CHAIN

四条链路：A 上游发布 · B 后台上传 · C R2→git→镜像 · D 排名测速

A/B 进 R2；C 从 R2 抽字节进 git；D 独立排序

链 A · 上游发布 → CDN

  • sync.yml：每天 4 窗 cron 17 1,7,13,19 * * *，或 workflow_dispatch 手动触发。
  • 镜像上游 release → 解包 → 上传 R2（assets/fonts/docs + 三张清单 data/*.json 绝对 URL 化）。
  • 发接口文件 cdn/v1/index|tree|api|art|mirrors 等 → 可选打 GitHub Release 包 + 部署 Pages。
  • 末尾自动 dispatch site.yml 刷新下载页快照。

链 B · 后台上传 → R2

  • 入口：管理员页 /admin，或命令行 tools/agent-upload.mjs / agent-upload-batch.mjs。
  • 字节落暂存区 cdn/incoming/<id>/ + claim.json。
  • 发布轮 promote-uploads.yml 逐字节核对 sha256 → CopyObject 到对外键（Cache-Control: immutable）。
  • 登记 hosted.json 进 git → 重发接口树 sync.mjs --write --interface-only（几十秒）。

链 C · R2 → git 树 → 各 git 镜像

  • git-art-sync.yml 把 R2 已上线后台上传的字节补提交进孤儿分支 assets-raw（一天 4 窗 + 链式触发）。
  • ① openi-mirror.yml 把该分支按文件级增量推到 OpenI（每天 4 次，单片约 60 MiB；OpenI 平台偶发连接超时，靠重试与多次运行追平）。
  • ② dataset-tree.yml 把整棵树分批推魔搭数据集 releases/v1-trial/**。⚠ 2026-10-14 起受阻：新树 1.78 GB 超数据集 1.6 GB 仓库上限被 pre-receive 硬拒（连拒 18 次），master 冻结在旧提交，处置待定。
  • ③ ghfast / jsDelivr / gitcdn-own 读 GitHub 的 assets-raw / main 分支（拉取型，自动跟随，无需推送）。

链 D · 排名与测速

  • rank.yml（每天 4 窗）生成 rank.json（Globalping 内地三运营商实测）→ 写 R2 + 镜像进魔搭数据集。
  • 容器边缘 asset-jump.js 每 5 分钟读它（主门牌 = 魔搭数据集 API，兜底 weishucdn）把合格的实测源排在头部。
  • network-measure.yml 每周一重测并触发 rank。
  • 与字节流解耦：只排顺序，不搬运素材。
镜像源清单（2026-10-15 实测）：① R2 桶（三域名，字节真源）；② 魔搭数据集 jingjiangze/Stronghold-Protocol-Assets@master:releases/v1-trial/（容器边缘默认跳转目标，覆盖约 54.5%，缺口目录级：voice 0% / char 21% / ui 20% / spine 45% / local 36%；2026-10-14 起因 1.6 GB 上限冻结、不再补齐，缺口需另行处置）；③ OpenI 启智（openi.pcl.ac.cn/.../raw/branch/assets-raw，最快但 CORS 写死第三方域不可用，仅 ?sp_source=openi 点名可达）；④ ghfast / jsDelivr（GitHub 代理，可用率低）；⑤ gitcdn-own（自有中转 Worker）；⑥ spages（Pages）。

UI

后台按钮怎么用（2026-10-15 起）

上传不再自动叫发布轮，避免打爆 Actions 队列

2026-10-15 起：后台上传不再自动叫发布轮——批量上传时每件叫一轮会把 Actions 队列打爆。 改为由管理员在 /admin 页面手动推进镜像链：

① 同步到镜像源（推荐）

  • 一次点击按顺序触发：① 发布轮（promote-uploads）→ ② git-art-sync.yml --write=true。
  • 下游由 git 链自动跟进：openi / dataset-tree 链式触发，无需再点。
  • 适合「上传完一批，整链推到镜像」的常规动作。

② 催一次发布 / 定时兜底

  • 「催一次发布」只跑发布轮（不推镜像）——仅想把字节上线、暂不碰 git 链时用。
  • 定时轮每 30 分钟仍作兜底：即便忘点按钮，暂存区字节也会被定期 promote。
  • 命令行等价：tools/agent-upload.mjs / agent-upload-batch.mjs 上传，发布轮由事件或定时驱动。
VERIFY

怎么核对（各步验收）

Actions 页 / 接口树 / 分支 / raw 链接 / 数据集 resolve 
# 1. 发布轮是否跑完（Actions 页看 promote-uploads.yml 绿）
gh run list --workflow=promote-uploads.yml --limit 5

# 2. 接口树已重发：tree.json 能取到、含刚上线的键
curl -s https://speedcdn.jiangjiangze.icu/cdn/v1/tree.json | head
curl -s https://weishucdn.jiangjiangze.icu/cdn/v1/tree.json | head   # 三域名同字节

# 3. git 中枢：assets-raw 分支有本次字节（git-art-sync 提交）
git ls-remote https://github.com/jingjiangze/Stronghold-Protocol-CDN assets-raw
git -C <本地仓> log --oneline origin/assets-raw -5

# 4. OpenI 镜像可达（raw 应 200 + 正确 MIME）
curl -sI https://openi.pcl.ac.cn/jingjiangze/Stronghold-Protocol/raw/branch/assets-raw/assets/char/avatar/char_1016_agoat2.png | grep -iE "HTTP|content-type"

# 5. 魔搭数据集补齐进度：resolve 链接能拉到对应路径
curl -sI "https://www.modelscope.cn/api/v1/datasets/jingjiangze/Stronghold-Protocol-Assets/repo?Revision=master&FilePath=releases/v1-trial/assets/char/avatar/char_1016_agoat2.png" | grep -iE "HTTP|location"

# 6. rank 支线：rank.json 已写、边缘读到（主门牌=数据集 API，兜底 weishucdn）
curl -s https://speedcdn.jiangjiangze.icu/cdn/v1/rank.json | head
接口文件只在 R2 桶域名上：/cdn/v1/*.json 只挂在 weishucdn / weishucdn2 / speedcdn，不挂在 git 镜像（OpenI / 数据集 / jsDelivr 等）。核对接口层一律用主门牌或三域名之一，别去 git 镜像找接口。
DEPRECATED

旧方案 mirror-modelscope.yml 把整树推魔搭创空间 cdn 分支， 被平台 1.6 GB 仓库上限硬拒（实测素材树 2.36 GB），已停用。素材树现改走 魔搭数据集 releases/v1-trial（dataset-tree.yml 分批推送）。 ⚠ 数据集同样撞上限（2026-10-14 起）：素材树累积到 1.78 GB 后，数据集 master 推送被 pre-receive 以 repo size(1784479944) greater than max repo size(1600000000) 连拒 18 次， 数据集内容冻结在旧提交（1.6 GB 上限是平台对仓库与数据集同口径的限制，数据集并未豁免）。 任何新文档 / 脚本都不要再引用创空间 cdn 分支同步——它不会成功，也没有回退计划。

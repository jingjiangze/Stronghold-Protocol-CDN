服务器部署文档

把卫戍协议游戏服从零部署到 ModelScope 创空间（一个 Docker 容器）。文档写清了：部署前 要准备什么信息、怎么创建创空间、默认配置是什么、怎么推送并触发重新部署、怎么验收， 外加一套不绑自有域名、也不用任何叠加层的最简部署方案。 所有默认配置都随配套仓库 Stronghold-Protocol-Server-Deploy 附上、逐字可用。 全部来自仓库源码与线上实测（2026-10-11，线上 build 5061a4e4 / app 0.2.3）。

端口 7860 锁死 最简 零叠加层 素材 直指 weishucdn
1 结论先行 创空间 = Docker 容器，端口硬锁 7860（2026-10-11）

游戏服跑在 ModelScope 创空间的 Docker 容器里，对外只暴露一个端口 7860（平台写死，不可改）。 最省事的部署是零叠加层：容器里只跑游戏进程，监听 7860；素材由清单里的绝对 https://weishucdn.jiangjiangze.icu/… 地址直接指到 CDN，浏览器自己取，字节不过容器。 配套仓库另带一套 nginx + sidecar 302 边缘层（边缘注入 / 多源兜底用），但线上清单已自带绝对 CDN 地址， 所以那层对 weishucdn 部署是可选、且已审计出局的——下面「零域名 · 零叠加层方案」就是最简路径。默认配置已写好，复制即用。

这是服务端部署，不是素材 CDN：本页讲「游戏服怎么跑起来」。素材本身由 既有 R2 / git 镜像分发（文档站其它页有素材 CDN 的同步与镜像说明）；游戏服只负责把清单里的素材地址 指向那些源。两者是不同系统，不要混。

TOPOLOGY

架构总览

游戏 3120 / sidecar 3130 / nginx 7860 
# 三个进程共用一个对外端口 7860，按路径分流
                    ┌─ /assets/** /fonts/** ─► edge-sidecar :3130 ──302──► 素材源（字节不过容器）
玩家 ──:7860──► nginx┤                                              ↑ 只有 Location，没有字节
                    └─ 其余（页面/data/js/vendor/media/ws/healthz）─► 游戏 :3120

为什么这么分

创空间只给一个公网口（7860），所以 nginx 占住它，另外两个退到内部端口（绑 127.0.0.1）。这与 Stardust 的 compose 同构（游戏 3120 / 素材解析器 3130 / 一个 nginx 在前面）。

监督语义是故意不对称的

  • 游戏或 nginx 退出 → 整体退出，让平台重启容器（少一个就没服务）。
  • sidecar 退出 → 只记日志；nginx 的 fallback 还能供素材，不为它重启整个容器。
STUDIO

第一步：创建 ModelScope 创空间

控制台 + Git 远程
  1. 1
    创空间里建仓库
    打开 ModelScope 创空间控制台 → 创建创空间；命名空间保持你的账号，仓库名填 Stronghold-Protocol；基础镜像选 node:22-alpine，硬件选 platform/2v-cpu-8g-mem。先别点部署。
  2. 2
    拿到 Git 仓库地址
    进创空间「设置」，复制 Git 仓库地址，形如 https://oauth2:<Token>@www.modelscope.cn/studios/jingjiangze/Stronghold-Protocol.git（Token 已嵌进 URL，无需 ssh key）。第 6 步当 git remote 用。
端口在控制台看不到输入框——它被平台的 deploy_schema.json 锁成 7860。记住它、别在 Dockerfile 里改端口即可；构建失败日志会提示端口约束。
CONFIG

第二步：默认配置（随配套仓库附上）

复制即用，逐字可用

下面这套是可选的「边缘层」（素材 302 / 多源兜底 / 边缘注入）。配套仓库 Stronghold-Protocol-Server-Deploy 把它的 5 个文件放在 deploy/stardust/ms-edge/，整目录复制进你的服务端代码即可（路径不变，根 Dockerfile 按这个路径 COPY）。 若走「零域名 · 零叠加层方案」（下一节），这 5 个文件一个都不用复制——游戏直接监听 7860，素材靠清单里的绝对 weishucdn 地址。

文件作用
sources.json源表与例外表（唯一真源，运行时读取）
edge-sidecar.mjs决策：路径校验、选源、302、CORS、方法限制（纯 Node，无 Lua）
nginx.conf分流 + 后端故障兜底（不含任何 Lua）
render-nginx.mjs构建期从 sources.json 渲染 sources-nginx.conf（定兜底基址）
entrypoint.sh三个进程的启动顺序与监督

Dockerfile 环境变量（写死）

ENV NODE_ENV=production \
    SP_PUBLIC_PORT=7860 \
    SP_GAME_PORT=3120 \
    SP_EDGE_PORT=3130 \
    PORT=3120 \
    HOST=127.0.0.1

sources.json 默认（节选）

{
  "order": ["modelscope", "r2"],
  "sources": [
    { "id": "modelscope",
      "base": "https://modelscope.cn/datasets/jingjiangze/Stronghold-Protocol-Assets/resolve/master/releases/v1-trial" },
    { "id": "r2",
      "base": "https://weishucdn.jiangjiangze.icu" }
  ],
  "exceptions": {
    "/assets/skins/char_340_shwaz_snow_1/illustration.png": "r2"
  }
}
order 是静态顺序，不是实时测速：容器在 ModelScope 机房，量不出玩家那边的链路。真正按玩家网络选最快是客户端 pick.js 的事，两者分工。新增镜像后要核对覆盖率——平台审核会拒收个别文件（如上面的 exceptions 路径），这些必须点名改道，否则玩家 404。
NAKED PLAN

零域名 · 零叠加层方案（最简）

不绑自有域名，不装 nginx+sidecar

这是给「只想让游戏服跑起来、不折腾代理」的人。它不申请自有域名、不套 Cloudflare Worker、也不装边缘层， 直接用平台分配的 *.ms.show 域名，容器里只跑游戏进程。前提：清单里的素材地址已经是 绝对 https://weishucdn.jiangjiangze.icu/…（线上就是）。不是「不绑 CDN」，而是不绑自有域名—— 素材依旧走 weishucdn，只是不经过任何叠在游戏前面的代理。

为什么可行

素材不过容器，靠清单绝对地址

玩家浏览器读 /data/assets.json 拿到的是完整 https://weishucdn.jiangjiangze.icu/… URL， 自己直连 CDN 取字节。容器既不用存素材，也不用 302 转发——边缘层的存在理由被清单直接抹掉了。

*.ms.show 域名能直接进游戏

平台 WAF 对浏览器 UA 放行 7860；但要塞进自有站点必须用 <iframe referrerpolicy="no-referrer">（直链会 302 到门户）。自定义 SNI / 自有域名在 WAF 层是默认证书， 接不通——所以本方案干脆不绑。

部署步骤

  1. 1
    准备一个只跑游戏的容器
    把服务端代码（server/ public/ data/ tools/）和下面这个极简 Dockerfile 放进创空间仓库即可，不要复制 deploy/stardust/ms-edge/。
  2. 2
    极简 Dockerfile
    游戏直接监听 7860（平台锁死的口），不再经 nginx 分流。环境里把端口暴露出来：
    FROM node:22-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
COPY server public data tools ./
ENV NODE_ENV=production \
    PORT=7860 HOST=0.0.0.0
EXPOSE 7860
CMD ["node", "server/index.js"]
  3. 3
    确认素材地址是绝对 weishucdn URL
    部署前一行命令核对清单：curl -fsS https://你的域名/data/assets.json | grep -c "https://weishucdn.jiangjiangze.icu"。 若清单里是相对路径（旧版），要么把游戏配成带 SP_ASSET_CDN 基址，要么退回上面的边缘层——否则玩家会 404。
  4. 4
    推送并点「重新部署」
    同「第三步」：git push ms HEAD:master 后，在创空间控制台点「重新部署」才会重新 build。
  5. 5
    把游戏塞进你的站点（不绑域名的关键）
    在自己的页面里用如下 iframe 内嵌，必须带 referrerpolicy="no-referrer"，否则 WAF 把直链 302 到 ModelScope 门户： 
    <iframe
  src="https://jingjiangze-stronghold-protocol.ms.show/"
  referrerpolicy="no-referrer"
  allow="autoplay; fullscreen"
  style="width:100%;height:80vh;border:0"></iframe>
取舍：零叠加层省掉了 nginx + sidecar 两个进程和一套源表，部署面更小、出问题的点更少； 代价是你不能做边缘注入 / 多源实时兜底（这些要靠清单本身带绝对地址）。自己搭的私有服没有这份 weishucdn 清单时， 还是得用边缘层或另配 SP_ASSET_CDN。本方案专为「用现成 weishucdn 清单」的场景。
DEPLOY

第三步：推送并触发重新部署

push ≠ 部署 
# 1) 加 ModelScope git 远程（oauth2 把 token 嵌进 URL）
git remote add ms "https://oauth2:${MS_TOKEN}@www.modelscope.cn/studios/jingjiangze/Stronghold-Protocol.git"

# 2) 提交默认配置（本机若开了 SSH 签字，用一次性覆盖避免 agent 缺失）
git add deploy/stardust/ms-edge Dockerfile
git -c commit.gpgsign=false commit -m "deploy: 内置边缘层默认配置（ms-edge）"

# 3) 推到创空间的 git 远程
git push ms HEAD:master

# 4) 推送后，在创空间控制台点「重新部署」——API 在 Running 态会拒绝 start
推送 ≠ 部署。推到创空间 git 远程只是落地代码；还要在控制台点「重新部署」（或调 API）才会重新 build。忘了这步，线上不会变。
VERIFY

第四步：验收

healthz / 素材地址 / WebSocket

curl -fsS https://jingjiangze-stronghold-protocol.ms.show/healthz

# 2. 清单里的素材地址必须是绝对 weishucdn URL（零叠加层不依赖 302）
curl -fsS https://jingjiangze-stronghold-protocol.ms.show/data/assets.json \
  | grep -c "https://weishucdn.jiangjiangze.icu"
#   → 若用边缘层（302 方案），则改成看 302：
# curl -fsS -o /dev/null -w '%{http_code} -> %{redirect_url}\n' \
#   https://…ms.show/assets/char/avatar/char_1016_agoat2.png

# 3. WebSocket（联机用）
wss://jingjiangze-stronghold-protocol.ms.show/ws
现象原因 / 处理
构建失败，nginx -t 错只在用边缘层时出现：sources.json 渲染不出 sources-nginx.conf，或 nginx.conf 语法错。零叠加层没有 nginx。
素材 404零叠加层：清单地址不是绝对 weishucdn URL（旧版相对路径），或 weishucdn 挂了；边缘层：命中 exceptions 没覆盖的被审核拒收路径，或 order 里的源挂了。
直链打开跳到 ModelScope 门户WAF 把裸 *.ms.show 直链 302 到门户。塞进自有站点必须 iframe referrerpolicy="no-referrer"；自定义域名在 WAF 层是默认证书，接不通。
push 成功但没生效忘了点「重新部署」。

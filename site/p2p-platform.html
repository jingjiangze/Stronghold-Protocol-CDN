异地联机

服务端内置接入 · openp2p 异地联机

玩家分散在各自家里、没有公网 IP 时怎么联机。由服务器自己接入平台：开房时向 p2p.jiangjiangze.icu 登记，拿回一条 joinUrl， 通过 room.state.inviteUrl 下发给房内所有人。玩家在游戏里点「复制链接」， 点开由平台发一条 302 决定去哪——隧道通就 p2p 直连，打不穿就回退到服务器。 不需要启动器，不需要玩家装任何东西。

平台 仅握手 游戏流量 不过平台 补丁 6 个文件 冒烟 30/30
1 整条链路一次讲清 服务器登记 → 下发链接 → 平台 302 → p2p 或回退

六个环节，从左到右。平台只在第 ⑤ 步出手一次——发一条 302，然后就不管了： 玩家浏览器自己连目标，游戏字节（含 WebSocket）从头到尾不经过平台、不经过阿里云 ECS。 

① 玩家开房（游戏客户端）
   room.create ─────────────────────────────────────────────► 服务器
                                                                    │
② 服务器异步登记（server/platform.js，4 s 超时）                │
   POST /api/room {hostNode, upstream, code} ────────────────► 平台
                                                              ◄──── roomId + joinUrl
                                                                    │
③ 服务器重播一次房间状态                                              │
   room.state.inviteUrl = https://p2p.jiangjiangze.icu/go/<id>?room=CODE
                                                                    │
④ 房主点「复制链接」发给朋友                                          │
   前端优先用 room.inviteUrl（没有就回落到本地 ?room= 链接）             │
                                                                    ▼
⑤ 玩家点开链接                                                        平台
   GET /go/<id> ────────────────────────────────────────────►  302
        │
        ├─ p2p 隧道通 ────────► http://127.0.0.1:<srcPort>/?room=CODE
        │                        （玩家自己本机的 openp2p 映射端口，游戏流量不经平台）
        │
        ├─ 隧道不通·有回退 ───► https://<upstream>/?room=CODE&o2pfallback=1
        │                        （回退到服务器联机；是重开一局，不是续局）
        │
        └─ 隧道不通·无回退 ───► http://127.0.0.1:3000/?room=CODE&o2pretry=1
                                 （提示本机重试）

⑥ 房间销毁
   disposeRoom ─ DELETE /api/room/<id>（尽力而为；平台侧 6 小时后自行过期）
「仅握手」是什么意思：平台 v3 不中转任何游戏流量、不下发 cookie、不反代。 ECS 默认 ShareBandwidth=0，只走信令，省下阿里云约 18G/月的出口额度。 代价是对局状态不能迁移——它只存在于游戏服进程内存里，所以 p2p 打不穿回退时， 所有人用同一个 code 重新开一局。发链接时记得提醒玩家。
STEPS

每步在哪个文件、发生什么

1 个新增文件 + 5 处接线
  1. 1
    启动：读环境变量，建接入实例
    server/index.js 调 platformConfigFromEnv(process.env)。 三个变量都不设 ⇒ 返回 null ⇒ platform = null，整条链路静默关闭， 行为与未接入时逐字节一致。
  2. 2
    开房：异步登记，fire-and-forget
    server/lobby.js 的 announcePlatformRoom()： room.create 成功后不阻塞地 POST /api/room。 solo 房跳过（没有人要邀请）。登记失败只写一行 warn，房间照常建。
  3. 3
    下发：重播一次 room.state
    登记成功才把 room.inviteUrl 写上并 broadcastState()； toState() 里它是可选字段（字符串或 null）。 旧客户端忽略未知键，所以 PROTOCOL_VERSION 保持 1。
  4. 4
    复制：前端优先用平台链接
    public/js/screens/room.js 的「复制链接」改成 room.inviteUrl || inviteLink(room.code)。 没有平台时这个表达式就是原来的本地链接，一处改动两种行为。
  5. 5
    跳转：平台只发一条 302
    GET /go/<id> 按房间类型决定 location：p2p 通 ⇒ 玩家本机映射端口； 不通 ⇒ 带 &o2pfallback=1 回退 upstream；无回退 ⇒ 本机 &o2pretry=1。平台不反代、不中转、不发 cookie。
  6. 6
    销毁：释放房间
    disposeRoom() 第一行 this.platform?.release(room.code) ⇒ DELETE /api/room/<id>，失败不重试（平台 6 小时自行过期）。

登记时发什么

  • p2p 模式：{hostNode, code, upstream}（hostNode 是房主节点名）
  • direct 模式：{upstream, code}（upstream 就是自己）
  • 同一房间 5 分钟内重复登记复用上次结果；并发登记只发一次请求

诊断端点

  • GET /api/platform ⇒ {enabled, mode, base, upstream, hostNode, rooms, lastOkAt, lastError}
  • 只有计数与配置，无玩家数据
  • 没配过平台时是 {"enabled":false}
CONFIG

三个环境变量

都不设 = 功能关闭，行为与未接入时完全一致
SP_PLATFORM_URL基址
平台基址，启动时读一次
默认 p2p.jiangjiangze.icu 0 / off 关闭
SP_PLATFORM_HOSTNODEp2p 开关
房主机器的 openp2p 节点名
8–63 位 字符集 [A-Za-z0-9._-]
SP_PLATFORM_UPSTREAM回退目标
打不穿时玩家去哪
p2p 模式 回退 direct 模式 就是自己

p2p 优先（设了 hostNode）

  • 登记 {hostNode, upstream, code}
  • 隧道通 ⇒ 302 到玩家本机 127.0.0.1:<srcPort>，游戏流量 p2p 直连、不经平台
  • 打不穿 ⇒ 302 到 SP_PLATFORM_UPSTREAM，带 &o2pfallback=1
  • 房主侧仍需跑一个 openp2p 节点（同名 + 开房返回的 token）

direct（线上 ms.show 默认）

  • 没设 hostNode ⇒ 登记 {upstream, code}
  • 平台只发一条 302 让玩家直连本服务器，腐竹零安装零节点
  • SP_PLATFORM_UPSTREAM 缺省时用 ModelScope 注入的 STUDIO_HOST / SPACE_HOST 推出自己的公网地址
  • 游戏会话字节走你自己的公网入口，不经 ECS 中转
ISOLATION

平台挂了，房间照常能打

接入是纯增益：坏的情况只损失一条远程链接

接入模块的每一条失败路径都指向同一个结果：inviteUrl 保持 null。 房间创建、加入、对局、断线重连全都不经过平台——它只负责「把一条链接递给玩家」。 这一条已用「平台指向死端口」实测过。

失败场景房间会怎样玩家看到什么
平台不可达 / DNS 失败 照常创建与联机，登记记 lastError 「复制链接」拿到本地 ?room= 链接
平台超时（4 s） 同上；登记是异步的，不阻塞开房 同上
平台返回非 2xx / 响应里没有 joinUrl 同上，inviteUrl 仍为 null 同上
收房时 DELETE 失败 不重试、不影响销毁，平台侧 6 小时后自行过期 无感
没配任何环境变量 platform = null，代码路径完全不进 与未接入时逐字节一致
协议不变：room.state.inviteUrl 是纯展示字段。 旧客户端会忽略未知键（validateC2S 跳过未知字段）， PROTOCOL_VERSION 保持 1——接入不需要客户端升级，也不需要房主升级。
VERIFY

怎么核对

四条命令，从开关到玩家视角 
# 1) 开关与模式（未配置时应为 {"enabled":false}）
curl -s http://127.0.0.1:3000/api/platform

# 2) 平台侧能看到服务器登记的房間
curl -s https://p2p.jiangjiangze.icu/api/rooms

# 3) 链接对不对：应是平台地址，而不是本机地址
#    浏览器进房 → 点「复制链接」→ 粘出来看
#    期望 https://p2p.jiangjiangze.icu/go/<id>?room=<4位密钥>

# 4) 关掉平台重启，房间照常能开、链接回落到本地 ?room=
SP_PLATFORM_URL=0 node server/index.js

上线 ms.show（direct，最省事）

  • 三个变量一个都不用设——默认基址就是主基址，direct 模式自己推 upstream
  • 覆盖 6 个文件 → 重启 → curl /api/platform 看到 "mode":"direct"
  • 腐竹零安装零节点，玩家点链接即达

自建机房 / VPS（p2p 优先）

  • 设 SP_PLATFORM_HOSTNODE（8–63 位节点名）
  • 设 SP_PLATFORM_UPSTREAM（打不穿时回退到哪）
  • 房主侧另跑 openp2p 节点：同名 + 开房返回的 int64 token（别加引号）
